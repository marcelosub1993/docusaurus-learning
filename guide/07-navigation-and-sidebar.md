# Módulo 07 — Navegação e sidebar

> **Objetivo:** assumir o controle do menu lateral, da navbar e do rodapé.
> **Tempo:** ~55 min
> **Pré-requisito:** [Módulo 06](./06-images-and-icons.md)

Até agora o menu se montou sozinho. Isso funciona bem para poucas páginas. Quando
a documentação cresce, você quer decidir a ordem, agrupar por assunto e misturar
links externos. É hora de abrir o `sidebars.js`.

💻 Dentro de `website`.

---

## Passo 1 — Ver o que está lá

📄 Abra `sidebars.js`. Ignorando os comentários, ele é isto:

```js
const sidebars = {
  tutorialSidebar: [{type: 'autogenerated', dirName: '.'}],
};

export default sidebars;
```

Lendo em voz alta: "existe uma sidebar chamada `tutorialSidebar`; o conteúdo dela
é gerado automaticamente a partir da pasta `docs/` inteira".

O nome `tutorialSidebar` não é mágico — é você quem escolhe. Ele é referenciado no
`docusaurus.config.js`, na navbar:

```js
{type: 'docSidebar', sidebarId: 'tutorialSidebar', position: 'left', label: 'Tutorial'},
```

⚠️ Se você renomear a sidebar aqui, **tem que renomear lá também**. O build falha
com `Can't find any sidebar with id "tutorialSidebar"` se você esquecer.

---

## Passo 2 — Descobrir os ids

Antes de escrever qualquer coisa à mão, você precisa saber os nomes que o
Docusaurus usa internamente. Como nenhuma página sua tem `id:` no front matter, o
id de todas vem do **caminho do arquivo dentro de `docs/`, sem a extensão**.

| Arquivo | id |
|---|---|
| `docs/intro.mdx` | `intro` |
| `docs/installation.mdx` | `installation` |
| `docs/reference.mdx` | `reference` |
| `docs/configuration/basic-setup.mdx` | `configuration/basic-setup` |
| `docs/faq/licensing.mdx` | `faq/licensing` |

⚠️ **O `slug` não muda o id.** A página de licenciamento tem `slug: /faq-licensing`,
mas o id dela continua `faq/licensing`. Slug é URL; id é o nome interno.

⚠️ **Mas o `id` muda a URL.** A relação não é simétrica, e é a
[cascata do Módulo 03](./03-first-page.md#passo-4--entendendo-slug-e-id):
`arquivo → id → slug → URL`. Se você um dia puser `id:` numa página para encurtar
o nome aqui no `sidebars.js`, saiba que a URL dela muda junto — a menos que você
fixe a URL com `slug`.

💻 Não confie na memória. Peça a lista de ids ao próprio Docusaurus:

```powershell
npm run build
```

👀 Se algum id estiver errado, a mensagem de erro imprime **todos os ids válidos**.
É a fonte da verdade, e sai de graça.

---

## Passo 3 — Assumir o controle

📄 Substitua o conteúdo de `sidebars.js` por:

```js
// @ts-check

/** @type {import('@docusaurus/plugin-content-docs').SidebarsConfig} */
const sidebars = {
  tutorialSidebar: [
    'intro',
    'installation',
    'reference',
  ],
};

export default sidebars;
```

👀 O menu agora tem exatamente três itens, nessa ordem — e as pastas
`configuration` e `faq` **sumiram**, porque você não as listou.

⚠️ As páginas continuam existindo: `/docs/configuration/basic-setup` ainda abre.
Elas só perderam o menu — e a paginação "Anterior/Próximo" junto. Uma página
fora de toda sidebar é uma página que ninguém encontra navegando.

⚠️ Se o terminal reclamar:

```
Invalid sidebar file at "sidebars.js".
These sidebar document ids do not exist: ...
```

Ele lista logo abaixo **todos os ids válidos**. Compare com o que você escreveu.

> A linha `/** @type {...} */` não é decoração: ela liga o autocomplete do VS
> Code. Digite `type: '` dentro de um item e pressione `Ctrl+Espaço` — o editor
> lista as opções válidas.

## Passo 4 — Os tipos de item

📄 Agora a versão completa, que traz tudo de volta e organizado. Substitua de novo:

```js
// @ts-check

/** @type {import('@docusaurus/plugin-content-docs').SidebarsConfig} */
const sidebars = {
  tutorialSidebar: [
    // 1. Shorthand: a bare string means {type: 'doc', id: 'intro'}
    'intro',

    // 2. Full form — label different from the page title
    {
      type: 'doc',
      id: 'installation',
      label: '⚡ Start here',
    },

    // 3. Section heading, with arbitrary HTML
    {
      type: 'html',
      value:
        '<div style="padding:0.75rem 1rem 0.25rem;font-size:0.7rem;font-weight:700;letter-spacing:0.06em;text-transform:uppercase;opacity:0.55;">Guides</div>',
      defaultStyle: false,
    },

    // 4. Category with an auto-generated index page
    {
      type: 'category',
      label: 'Configuration',
      collapsed: false,
      link: {
        type: 'generated-index',
        title: 'Configuration guides',
        description: 'Everything you can adjust in Nimbus.',
        slug: '/category/configuration',
      },
      // Picks up every file in the folder, ordered by sidebar_position
      items: [{type: 'autogenerated', dirName: 'configuration'}],
    },

    // 5. Visual separator
    {
      type: 'html',
      value: '<hr style="margin:0.75rem 1rem;opacity:0.2;" />',
      defaultStyle: false,
    },

    'reference',

    {
      type: 'category',
      label: 'Frequently asked questions',
      collapsed: true,
      items: [{type: 'autogenerated', dirName: 'faq'}],
    },

    // 6. External link — gets the "leaves the site" icon automatically
    {
      type: 'link',
      label: 'Docusaurus docs',
      href: 'https://docusaurus.io/docs',
    },
  ],
};

export default sidebars;
```

👀 Confira cada item no navegador. Clique no nome "Configuration" — abre a página
de índice com cards.

### O `_category_.json` para de valer aqui

⚠️ **Quando você declara a categoria à mão, o `_category_.json` daquela pasta é
ignorado por completo** — `label`, `position`, `collapsed`, `link`, tudo.

💻 Vale testar para acreditar. 📄 Troque o `label` do
`docs/configuration/_category_.json` por `ZZZ-TESTE` e rode:

```powershell
npm run build
Select-String -Path build -Pattern "ZZZ" -Recurse
```

👀 Nenhum resultado. O arquivo inteiro foi ignorado.

O motivo: `_category_.json` é o arquivo de configuração da **autogeração**. Ele
descreve como uma pasta deve virar categoria quando o Docusaurus monta o menu
sozinho. A partir do momento em que você escreve a categoria no `sidebars.js`,
quem manda é o que está escrito lá.

E repare no detalhe do item 4: `items: [{type: 'autogenerated', dirName: 'configuration'}]`
autogera **o conteúdo** da pasta, não a pasta como categoria. A categoria é sua; só
os filhos são automáticos.

| | Sidebar 100% autogerada | Categoria declarada à mão |
|---|---|---|
| Nome da categoria | `_category_.json` → `label` | `sidebars.js` → `label` |
| Ordem | `_category_.json` → `position` | **A ordem do array** |
| Recolhida ou não | `_category_.json` → `collapsed` | `sidebars.js` → `collapsed` |
| Página de índice | `_category_.json` → `link` | `sidebars.js` → `link` |

⚠️ **E não existe `position` no `sidebars.js`.** Procurar por ele é o erro natural
de quem vem do `_category_.json` — o tipo `SidebarItemCategory` aceita `label`,
`collapsed`, `collapsible`, `description`, `items` e `link`, e mais nada. Numa
sidebar manual a ordem é **a ordem em que você escreveu os itens no array**: mover
a categoria três linhas para cima é como se muda a posição dela.

💡 **Então apago os `_category_.json`?** Pode, mas vale deixar. Eles não atrapalham
e voltam a valer no instante em que você trocar aquela categoria por um
`{type: 'autogenerated', dirName: '.'}` — ou seja, se um dia você desistir do menu
manual.

### O `type: 'html'` não tem rede de segurança

Repare no que os itens 3 e 5 são: uma **string** com HTML dentro, escrita num
arquivo `.js`. Nada ali é verificado — nem o HTML, nem o CSS. O Docusaurus
entrega a string para a página e pronto.

Na prática, três coisas erram em silêncio:

**1. CSS separado por vírgula em vez de ponto e vírgula.**

```html
style="padding:0.5rem, font-size:0.7rem, font-weight:700; opacity:0.55"
```

O navegador quebra o `style` por **`;`**. Tudo antes do primeiro `;` vira **uma
única declaração**, que é inválida e é descartada inteira — padding, font-size e
font-weight somem juntos. Só o `opacity` sobrevive, e você não recebe aviso
nenhum.

**2. Espaço dentro de um valor.**

`margin:0.75rem 1 rem` não é `0.75rem 1rem`. É `0.75rem`, `1`, `rem` — três
valores, dois inválidos. A declaração inteira cai.

**3. Pontuação solta perto das aspas.**

```html
<hr style="opacity:0.2"; />     ← o ; depois das aspas
```

Esse é o único dos três que **dá sinal**, no fim do build:

```
[WARNING] Docusaurus static site generation process emitted warnings for 9 paths
  - [HTML minifier diagnostic - error] Missing whitespace between attributes
```

O Módulo 99 explica [como ler esse aviso](./99-troubleshooting.md#docusaurus-static-site-generation-process-emitted-warnings).

💻 **Como conferir seus itens `html`:** depois do build, procure o que você
injetou no HTML gerado e leia com calma:

```powershell
npm run build
Select-String -Path "build\docs\index.html" -Pattern "<hr|>Guides<"
```

💡 **A saída melhor:** quando o CSS passa de duas ou três propriedades, tire-o da
string. Crie uma classe no `src/css/custom.css` e use só `class` no `value`:

```js
{
  type: 'html',
  value: '<div class="sidebar-section-title">Guides</div>',
  defaultStyle: false,
},
```

```css
/* src/css/custom.css */
.sidebar-section-title {
  padding: 0.75rem 1rem 0.25rem;
  font-size: 0.7rem;
  font-weight: 700;
  letter-spacing: 0.06em;
  text-transform: uppercase;
  opacity: 0.55;
}
```

O editor passa a verificar o CSS, você não escapa aspas, e a mesma classe serve
para os próximos títulos de seção.

⚠️ Aqui é `class`, não `className` — esta string é **HTML de verdade**, não JSX.
É a exceção à regra do [Módulo 08](./08-components-and-layout.md).

### Referência dos tipos

| Tipo | Para quê |
|---|---|
| `doc` | Aponta para um documento |
| `category` | Agrupa itens; pode aninhar sem limite de profundidade |
| `link` | URL externa ou interna, escrita à mão |
| `html` | HTML arbitrário: separador, título de seção, badge |
| `ref` | Como `doc`, mas não gera "Anterior/Próximo" nem marca página ativa |
| `autogenerated` | Expande uma pasta inteira naquele ponto |

### A estratégia recomendada

**Estrutura manual, conteúdo autogerado** — foi o que os itens 4 e 7 fazem. Você
decide a ordem e o nome das seções; dentro de cada seção, um arquivo novo aparece
sozinho. Controle onde importa, zero manutenção onde não importa.

O custo do 100% manual: toda página nova exige editar o `sidebars.js`, e esquecer
disso significa página invisível. O custo do 100% automático: você fica refém do
`sidebar_position` e não consegue separadores nem links externos.

## Passo 5 — As três formas de clicar numa categoria

O campo `link` da categoria define o que acontece ao clicar no nome dela:

| `link` | Comportamento |
|---|---|
| `{type: 'generated-index'}` | Abre uma página com cards de todos os filhos. Zero manutenção. |
| `{type: 'doc', id: 'configuration/basic-setup'}` | Abre um documento seu, escrito à mão, como capa da seção. |
| omitido | A categoria só expande e recolhe. Sem página própria. |

💻 Experimente as três na categoria Configuration, uma de cada vez, salvando e
olhando o navegador. A segunda é a melhor quando a seção merece uma introdução de
verdade; a primeira, quando não merece.

📄 Deixe no `generated-index` para seguir.

## Passo 6 — Múltiplas sidebars

Sites grandes separam assuntos que não se misturam — "User guide" e "API
reference", por exemplo. Cada sidebar aparece só nas páginas que ela contém.

```js
const sidebars = {
  guideSidebar: ['intro', 'installation', {type: 'category', label: 'Configuration', items: [/* ... */]}],
  apiSidebar: ['api/overview', 'api/endpoints'],
};
```

Cada uma ganha seu próprio item na navbar:

```js
{type: 'docSidebar', sidebarId: 'guideSidebar', position: 'left', label: 'Guide'},
{type: 'docSidebar', sidebarId: 'apiSidebar', position: 'left', label: 'API'},
```

⚠️ Um documento em duas sidebars diferentes gera aviso — o Docusaurus não sabe
qual menu mostrar quando o usuário chega nele. Se precisar repetir, use
`type: 'ref'` na segunda.

## Passo 7 — A navbar

📄 Em `docusaurus.config.js`, dentro de `themeConfig.navbar`:

```js
navbar: {
  title: 'Nimbus',
  logo: {alt: 'Nimbus logo', src: 'img/logo.svg'},
  hideOnScroll: false,
  items: [
    // Opens the docs sidebar
    {type: 'docSidebar', sidebarId: 'tutorialSidebar', position: 'left', label: 'Docs'},

    // Dropdown menu
    {
      type: 'dropdown',
      label: 'Resources',
      position: 'left',
      items: [
        {type: 'doc', docId: 'reference', label: 'Syntax reference'},
        {to: '/docs/category/configuration', label: 'Configuration'},
        {href: 'https://docusaurus.io', label: 'Docusaurus ↗'},
      ],
    },

    {to: '/blog', label: 'Blog', position: 'left'},
    {
      href: 'https://github.com/your-username/docusaurus-learning',
      label: 'GitHub',
      position: 'right',
    },
  ],
},
```

👀 A navbar muda sozinha ao salvar — `themeConfig` recarrega. Se não mudar,
`Ctrl+C` e `npm start`.

### Diferença entre `to` e `href`

- **`to`** — link interno. Navegação instantânea, sem recarregar a página, e
  **validado no build**.
- **`href`** — link externo. Recarrega, e ganha o ícone de link externo.

Usar `href` para uma página interna funciona, mas perde a navegação rápida e a
validação. Usar `to` para um site externo simplesmente não funciona.

### Itens especiais

```js
{type: 'docsVersionDropdown', position: 'right'},  // version selector
{type: 'localeDropdown', position: 'right'},       // locale selector
{type: 'search', position: 'right'},               // positions the search bar
```

Os dois primeiros só fazem sentido quando o recurso existe — veja o
[Módulo 11](./11-advanced-features.md). O terceiro só serve para **mover** a
caixa de busca; ele não instala busca nenhuma.

## Passo 8 — Três ajustes que o tema gera sozinho

Breadcrumbs, paginação e "Edit this page" não são coisas que você escreve: o tema
monta os três a partir da estrutura que você já tem. O que você faz aqui é
**ajustar** cada um, e eles moram em lugares diferentes do config.

### Antes: existem DOIS blocos chamados `docs` no config

Esta é a maior fonte de confusão deste passo, então vale ver o mapa antes:

```js
const config = {
  presets: [
    ['classic', ({
      docs: { ... },        // ← (A) opções do PLUGIN de docs
      blog: { ... },
      theme: { ... },
    })],
  ],

  themeConfig: ({
    image: '...',
    colorMode: { ... },
    docs: { ... },          // ← (B) opções do TEMA  (não existe, você cria)
    navbar: { ... },
    footer: { ... },
  }),
};
```

E os dois aceitam coisas **completamente diferentes**:

| Bloco | Onde | Aceita |
|---|---|---|
| **(A)** `presets` → `classic` → `docs` | Já existe | `sidebarPath`, `editUrl`, `routeBasePath`, **`breadcrumbs`**, `tags`, `onInlineTags`, `versions`… |
| **(B)** `themeConfig` → `docs` | Você cria | Só três: `versionPersistence`, `sidebar.hideable`, `sidebar.autoCollapseCategories` |

⚠️ **Não existe regra mnemônica aqui.** Seria natural supor que "aparência vai no
`themeConfig`", mas `breadcrumbs` é aparência pura e mora no bloco (A). A divisão
é histórica: o bloco (A) é do **plugin de docs**, que gera quase tudo; o (B) é do
**tema**, e só tem três chaves.

💻 Na dúvida sobre onde uma opção mora, deixe o Docusaurus responder — ponha no
lugar errado e leia o erro:

```
"docs.breadcrumbs" is not allowed
path: [ 'docs', 'breadcrumbs' ]
```

Essa mensagem quer dizer: *o `docs` do `themeConfig` não conhece `breadcrumbs`*.
Ou seja, é do outro bloco.

### 8.1 — "Edit this page" (este está quebrado, conserte)

👀 Role até o rodapé de qualquer documento. Existe um link **"Edit this page"**.
Clique nele: você cai no repositório do **Facebook**, não no seu.

Isso vem do `editUrl`, que o template deixou apontando para o repositório de
exemplo do Docusaurus. Ele aparece **duas vezes**.

💻 Ache os dois:

```powershell
Select-String -Path "docusaurus.config.js" -Pattern "editUrl" -Context 0,1
```

👀 Linhas ~52 e ~63, dentro de `presets` → `classic` — uma no bloco `docs`, outra
no bloco `blog`. As duas têm o mesmo valor:

```js
editUrl:
  'https://github.com/facebook/docusaurus/tree/main/packages/create-docusaurus/templates/shared/',
```

📄 Troque **as duas** por:

```js
editUrl: 'https://github.com/your-username/docusaurus-learning/tree/main/website/',
```

💻 Reinicie o `npm start` — opção de preset não recarrega sozinha
([Módulo 02](./02-creating-the-site.md#o-que-recarrega-sozinho-e-o-que-não)).

👀 Clique em "Edit this page" na página de instalação. A URL tem que ser:

```
https://github.com/your-username/docusaurus-learning/tree/main/website/docs/installation.mdx
```

Repare no que aconteceu: o Docusaurus **colou** `docs/installation.mdx` no fim do
que você escreveu. Por isso o `editUrl` termina em `website/` — ele aponta para a
raiz do site, e o plugin completa o caminho do arquivo.

⚠️ Se o seu terminar em `website/docs/`, o link vai dar 404 com
`docs/docs/installation.mdx`.

Para tirar o link de **uma** página: `custom_edit_url: null` no front matter dela.
Para tirar de **todas**: apague a opção `editUrl` inteira (as duas linhas de
comentário acima dela também).

---

### 8.2 — Breadcrumbs (opcional, experimente e decida)

👀 Abra `/docs/configuration/basic-setup`. No topo do conteúdo há uma trilha:

```
Docs  ›  Configuration  ›  Basic setup
```

Ela é montada a partir da **sidebar**, não das pastas. Se você mudar a ordem no
`sidebars.js`, a trilha acompanha.

📄 Para desligar, acrescente `breadcrumbs: false` no bloco **(A)** — dentro de
`presets` → `classic` → `docs`, ao lado do `sidebarPath`:

```js
presets: [
  [
    'classic',
    ({
      docs: {
        sidebarPath: './sidebars.js',
        // highlight-next-line
        breadcrumbs: false,
        editUrl: 'https://github.com/your-username/docusaurus-learning/tree/main/website/',
      },
```

💻 Reinicie e olhe a mesma página.

👀 A trilha sumiu.

⚠️ **Não é no `themeConfig`.** Se você puser lá, o build morre com:

```
"docs.breadcrumbs" is not allowed
```

É o bloco errado dos dois do mapa acima. O `themeConfig.docs` só conhece
`versionPersistence` e `sidebar`.

📄 Volte para `true` (ou apague a linha) se preferir com — não há resposta certa:
em site raso a trilha incomoda, em site profundo ela ajuda.

💡 **Já que você está no `themeConfig`,** as três chaves do bloco (B) valem
conhecer. Esta deixa o leitor esconder a sidebar inteira com um botão no rodapé
dela:

```js
themeConfig: ({
  docs: {
    sidebar: {
      hideable: true,
      autoCollapseCategories: false,
    },
  },
```

👀 Com `hideable: true`, aparece uma seta no canto inferior da sidebar. Útil em
documentação com páginas largas — tabelas e blocos de código grandes.

---

### 8.3 — Paginação (por página, no front matter)

👀 No rodapé de cada documento há dois botões, **Previous** e **Next**. A ordem
deles vem da sidebar.

Às vezes você quer forçar. 📄 Em `docs/installation.mdx`, acrescente ao front
matter:

```mdx
---
title: Installing Nimbus
sidebar_label: Installation
sidebar_position: 1
pagination_next: configuration/basic-setup
---
```

👀 O botão **Next** da página de instalação agora aponta para Basic setup, mesmo
que a sidebar diga outra coisa.

⚠️ O valor é o **id**, não a URL nem o nome do arquivo. É a tabela do
[Passo 2](#passo-2--descobrir-os-ids): `configuration/basic-setup`, com a pasta
junto e sem a extensão.

Os dois campos:

| Campo | Efeito |
|---|---|
| `pagination_next: <id>` | Força o botão Next |
| `pagination_prev: <id>` | Força o botão Previous |
| `pagination_next: null` | **Remove** o botão Next desta página |

💡 Útil quando uma página é um beco sem saída (um FAQ, por exemplo) e você não
quer empurrar o leitor para a próxima da lista.

## Passo 9 — O rodapé

📄 Ainda em `docusaurus.config.js`, substitua o `footer` do template:

```js
footer: {
  style: 'dark',
  logo: {alt: 'Nimbus logo', src: 'img/logo.svg', href: '/', width: 48},
  links: [
    {
      title: 'Documentation',
      items: [
        {label: 'Get started', to: '/docs/installation'},
        {label: 'Configuration', to: '/docs/category/configuration'},
        {label: 'Syntax reference', to: '/docs/reference'},
      ],
    },
    {
      title: 'Support',
      items: [
        {label: 'Frequently asked questions', to: '/docs/faq-licensing'},
        {label: 'Report an issue', href: 'https://github.com/your-username/docusaurus-learning/issues'},
      ],
    },
    {
      title: 'More',
      items: [
        {label: 'Blog', to: '/blog'},
        {label: 'GitHub', href: 'https://github.com/your-username/docusaurus-learning'},
      ],
    },
  ],
  copyright: `Copyright © ${new Date().getFullYear()} Nimbus. Built with Docusaurus.`,
},
```

O `copyright` é uma template string JavaScript — por isso o
`${new Date().getFullYear()}` funciona e o ano nunca fica desatualizado. Ele
também aceita HTML.

⚠️ Repare que os links de Stack Overflow, Discord e X do template sumiram. Eles
apontavam para o projeto Docusaurus, não para o seu. Deixar isso num site
publicado é o descuido mais visível que existe.

💻 Valide tudo:

```powershell
npm run build
```

👀 Se algum `to:` apontar para uma rota que não existe, o build falha e diz qual.
Este é o `onBrokenLinks: 'throw'` protegendo você de novo.

## 🎯 Exercício

Reorganize o site como se fosse entregar para um usuário real.

**1. Duas sidebars**

📄 Em `sidebars.js`, quebre `tutorialSidebar` em duas:

```js
const sidebars = {
  guideSidebar: [
    // intro, installation, the Configuration category and the FAQ
  ],
  referenceSidebar: [
    // reference, plus an external link to the Docusaurus docs
  ],
};
```

**2. Um item de navbar para cada**

📄 Em `docusaurus.config.js`, dois itens `docSidebar` — "Guide" e "Reference".

⚠️ Aqui você vai encontrar o erro `Can't find any sidebar with id
"tutorialSidebar"`. Ele é esperado: você renomeou a sidebar e o item antigo da
navbar ficou apontando para o nome velho. Leia a mensagem e conserte.

**3. Uma capa escrita à mão para a seção Configuration**

📄 Troque o `link` da categoria de `generated-index` para
`{type: 'doc', id: 'configuration/basic-setup'}` e veja a diferença.

Depois decida qual você prefere e deixe assim. Anote o porquê no `guide/NOTES.md`.

**4. Experimente os breadcrumbs**

📄 Desligue com `docs: {breadcrumbs: false}`, olhe o site, e decida. Não existe
resposta certa — em site raso incomodam, em site profundo ajudam.

**5. Force a paginação**

📄 Em `docs/installation.mdx`, adicione `pagination_next: configuration/basic-setup`
no front matter.

👀 O botão "Next" no rodapé da página passa a apontar para lá, mesmo que a ordem
da sidebar diga outra coisa.

**6. Valide e commite**

**Como saber que deu certo:**

- A navbar tem "Guide" e "Reference", e cada um abre um menu lateral diferente
- Ao navegar para `/docs/reference`, o menu lateral **troca**
- Nenhuma página ficou fora das duas sidebars (teste clicando em tudo)
- O botão "Next" da instalação vai para Basic setup
- `npm run build` passa sem avisos

## 📌 O que você aprendeu

`sidebars.js` controla o menu lateral; `themeConfig.navbar` e `themeConfig.footer`
controlam o topo e o rodapé. A combinação mais prática é estrutura manual com
conteúdo autogerado. Sidebar usa **id**, navbar e footer usam **URL** — e
breadcrumbs e paginação são derivados da sidebar, então organizar bem o menu
melhora três coisas de uma vez.
